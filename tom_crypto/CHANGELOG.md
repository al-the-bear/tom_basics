## 1.1.0

- **Fixed: secure random bytes could never take the value `255`.** Both places
  that drew raw randomness used `Random.nextInt(255)`, whose bound is exclusive,
  so every generated byte fell in `0..254`. This affected the Fortuna seed in
  `RsaKeyHelper.getSecureRandom` (and therefore every RSA key pair) and the salt
  in `TomPasswordHasher.generateSalt` (which is hex-encoded into the stored
  `salt$hash`). The loss is about 0.0056 bits per byte. Existing password hashes
  remain verifiable — the salt is stored alongside the hash — so no migration is
  required.
- **Added: `TomSecureBytes.generate`**, now the single source of raw randomness
  in this package. Both call sites above previously carried their own copy of the
  same draw loop, and both copies were wrong in the same way; there is now one
  implementation for a third copy to not drift from.
